** 编译
*** 1. preprocess
主要是把 #include xxx.h 这种东西替换为 xxx.h source file 里面的文本, 对 macro 进行文字替换
比如说 #include "xxx.h" 在 preprocess 阶段做的就是把 xxx.h 文件的文本复制过来, 替换 #include "xxx.h" 这一行
我们上面写 guard, 即 #ifndef XXXX_H 的原因就是, 你可能在一个 source file 里面 include 了同一个文件多次, 这样你重复 declare 了一个东西多次, 可能会报错, 你加这个东西, 就会先判断, 然后如果没 include 过再 include, 保证一个文件只被 include 一次

*** 2. compile
编译器把 xxx.c 文件独立编译成对应的机器码 .o 文件, 每个 .c 文件独立编译, 未实现但是有声明是可以的, 只要语法正确即可
这个意思是说, 假如你在 xxx.h 里面写了某个函数的 declaration, 然后在 yyy.c 里 #include "xxx.h", 然后你在 xxx.c 里面实现了 xxx.h 里面 declare 的函数, 你在编译 yyy.o 的时候, yyy.c 里面并没有这个 xxx.h 里声明的函数的实现, 即使你不写 xxx.c 这个编译也是成功的

在 vim 里面查看二进制文件 ( elf 格式: :%!xxd, %表示全局, !表示外部命令, xxd 是一个解析二进制码的工具 ), 是时候对 vim 再进一步了

编译常见 option
a. -std=gnu99: 使用什么规范什么标准
b. -c: compile only, 不 link
c. -g: enable gdb debug, debug 选项
d. -O0: 优化与否, -O0 表示不优化便于 debug, 数字越大表示优化的越厉害
e. 关于容错和警告: -Wall 是 warning all 的意思, 警告大部分错误 ( 尽管声称是 warning all ), -Wextra 额外警告, 比 -Wall 更多, -pedantic 严格遵循标准 ( 学究 )

*** 3. link
把各个 .o 文件链接起来, 生成 executable image, 这个时候会有什么重复定义, 声明了没找到这些问题
比较 tricky 的地方是, 即使你在 xxx.c 里面不 #include xxx.h ( xxx.c 里面实现了 xxx.h 里面声明的函数 ), 编译器还是可以正确 link 的, 只不过没人这么干

当然, 很多时候在写 gcc 指令的时候, 我们不分开 compile 和 link, 两个是一起的

常见指令: gcc ..... -o executable, -o 后面的名字是 executable image, 然后 ./executable 就可以执行命令了
g++ -std=c++1y  -lpng -lpthread -lm xxx.o o executable
-lpng 前面的 -l 表示 lib, 然后 png 是系统 lab 库, 一般在 /usr/lib/x86_64-linux-gnu 这个里面, 里面有 .so 这种动态库 ( ros 2 control 里面用的那个 ), 也有 .a 这种静态库, 我们可以使用 file 指令查看这个东西的性质, 比如:

下面是简化版的 .ld 文件, 用于展示内存布局的

#+begin_src conf
/* Entry Point */
ENTRY(Reset_Handler)

/* Highest address of the user mode stack */
_estack = ORIGIN(DTCMRAM) + LENGTH(DTCMRAM);    /* end of RAM */
/* Generate a link error if heap and stack don't fit into RAM */
_Min_Heap_Size = 0x200;      /* required amount of heap  */
_Min_Stack_Size = 0x400; /* required amount of stack */

/* specify memory sections */
MEMORY
{
DTCMRAM (xrw) : ORIGIN = 0x20000000, LENGTH = 128K  /* DTCM, CPU 专属访问读写极快, Dtat TCM, 主要放的是 CPU 高频访问的数据 */
RAM_D1  (xrw) : ORIGIN = 0x24000000, LENGTH = 320K  /* SRAM Region 1, rwx 都行, 可被 CPU/DMA/外设访问, 访问延迟大于 TCM  */
RAM_D2  (xrw) : ORIGIN = 0x30000000, LENGTH = 32K   /* SRAM Region 2, 同上 */
RAM_D3  (xrw) : ORIGIN = 0x38000000, LENGTH = 16K   /* SRAM Region 3, 同上 */
ITCMRAM (xrw) : ORIGIN = 0x00000000, LENGTH = 64K   /* ITCM, CPU 专属访问极快, Instruction TCM, 极端实时的代码指令 */
FLASH   (rx)  : ORIGIN = 0x08000000, LENGTH = 1024K /* FLASH, 只能 rx, 不能 w, 因此一般放不会修改的东西, 比如常量, 程序代码, 向量表 */
}

/* Define output sections */
SECTIONS
{
        /* The startup code goes first into FLASH */
        .isr_vector : { /* 中断向量表, 在 FLASH 开头 */ } >FLASH

        /* The program code and other data goes into FLASH */
        .text : { /* 所有程序, .text 和 .text* 的都放在这里 */ } >FLASH

        /* Constant data goes into FLASH */
        .rodata : { /* 常值, .rodata 和 .rotata*, ( constants, strings, etc. ) */ } >FLASH

        /* ARM 特定段, 没研究过, 但是这俩都是 READONLY 的, 也在 FLASH */
        .ARM.extab : { /* ARM异常处理表 */ } >FLASH
        .ARM : { /* ARM异常索引表 */ } >FLASH

        /* 给 cpp 的, 我的 stm32 里面是纯 c, 没有 cpp, 没研究过 */
        .init_array : { /* C++静态构造函数数组 */ } >FLASH
        .fini_array : { /* C++静态析构函数数组 */ } >FLASH

        /* C/CPP 初始化, 没研究过 */
        .preinit_array (READONLY) : { /* C++/C 运行时初始化机制的一部分，用于在 main 函数之前执行初始化代码 */ } >FLASH

        /* Initialized data sections goes into RAM, load LMA copy after code */
        /* 运行时在 DTCMRAM 中, 加载时在 FLASH 中, 启动时把 FLASH 中的初始值 memcpy 到 DTCMRAM 中的 .data 对应位置 */
        .data : { /* 有初始值的 "静态存储期对象", 如全局变量, static 全局, static 局部 * / } >DTCMRAM AT> FLASH

        /* Uninitialized data section */
        .bss : { /* 没有显式初始化的静态存储期对象, 不占 Flash 直接放 DTCMR, 如未初始化的全局/static 全局/static 局部 */ } >DTCMRAM

        /* buffer specified for dma1 and dma */
        .dma12_buffer (NOLOAD) : { /* DMA 没有办法访问 DTCM, 所以给开一个地方在 SRAM 上面 */ } >RAM_D2

        /* User_heap_stack section, used to check that there is enough RAM left */
        ._user_heap_stack : { /* user 使用的 heap 段, 用于 malloc */ } >DTCMRAM

}
#+end_src

你会发现这里没有 stack 的地方, 这个是因为 stack 不是预先规定的, stack 是 CPU 的 SP 寄存器 + RAM 空间
规定一下 convention, 一般称地址较大的为高地址, 地址较小的为低地址, 比如说 0x0010 和 0x1000, 0x1000 算高地址, 0x0010 算低地址
stack top: 当前 stack pointer 指向的位置, stack bottom: stack 被分配的那一端的边界
主流 CPU 上, stack 是从高地址向低地址生长, PUSH 代表 SP 减少, POP 代表 SP 变大,
_estack 代表 stack 的分配边界, 最高的那个地址, stack pointer 从 _estack 这个地址开始向低地址生长, 有一些恶心的 bug 比如说 stack 长到了 heap 里面
stack overflow: stack 踩到了 heap 和 .bss 段

** variable 相关
关于变量存储位置, 作用域, 生命周期, 非常重要

1. 一般局部变量, 即函数内部使用的一般变量 (无static关键字), 作用域是该函数体内部, 储存位置在 run time stack 上面, 生命周期是函数被调用时创建/初始化, 到函数 return 时生命周期结束, 比如 void function(int a, int b) {} 里面的 c 这个局部变量
   这个在 ECE220 写 run time stack 的 lc3 汇编的时候已经学的很明白了
2. static 局部变量, 一般的局部变量加上一个 static 关键字, 比如. void function(int a, int b) { static int c = a + b; }, 这个变量的作用域也是该函数内部, 即只有该函数内部才能访问这个变量, 但是这个变量的生命周期是整个程序执行的时间, 主要放在 .data/.bss 段 ( 取决于有没有初始化 )
3. 全局变量, 如直接写在 .c 文件里 ( 不在任何一个函数内部 ), 作用域是全部程序 ( 注意, 如果 local variable 和 global variable 重名, 那在函数内使用的是 local 的 ), 即任何一个程序都可以访问 ( 使用这个全局变量的程序要有 extern 关键字声明这个变量存在 ), 否则无法直接使用, 这个东西的储存位置在 .bss 或者 .data 段 ( 取决于有没有初始化 ), 生命周期是整个程序的执行时间, 注意, 全局变量的名字不能重复
4. static 全局变量, 跟全局变量唯一的区别是作用域被限定为了这个 .c 文件, 只有这个文件里的函数可以使用

** c关键字和 GCC 提示指令
1. extern
   用于声明全局变量的

   比如说在 xxx.c 里面写了 extern int a;, 声明这里有一个全局变量 a, 但是在别的地方不知道在哪里 ( 可能在别的文件, 也可能在这个文件的后面 ), 但是我 extern int a; 声明之后, xxx.c 后面的内容就可以使用 a 这个变量了

   我们有时候会这样 (这个实际上是使用全局变量的标准模式), 在 xxx.h 里面写 extern int a;, 然后在 xxx.c 里面写 int a = 0;, 当你在其他 .c 文件里 #include "xxx.h" 之后, 经过 preprocess, extern int a; 这个声明会出现在其他文件里, 让其他文件可以访问这个全局变量, 在 xxx.c 里, 你 #include "xxx,h", preprocess 的时候有了 extern int a; 这个声明, 然后你在后面写 int a = 0;, 给了变量 a 这个定义

2. static
   表示 local, 表示这个东西仅属于当前 函数/文件, 其他 函数/文件 用不了, 这个使得我们可以重名, 比如说在 xxx.h 里面写 static int add(int a, int b) {return a + b};, 然后不同 #include "xxx.h" 的 c 文件都有这个 add 函数的 local 版本, 不会出问题, 但是如果你没有写 static, 就会出现很多个 add 函数 ( 没有 static 的时候, 这个函数默认是 global 的 ), 这个时候编译器就会报错

   static 的 variable 在 .bss 或者 .data 段, static 的函数在 .text 段, 但是只有该函数/文件可以使用

3. inline
   用于内联, 内联是一种编译器优化，建议编译器把函数调用替换为函数体本身

   如果没有内联                                      内联之后
   int square(int x) { return x * x; }             inline square(int x) {return x * x;}
   int y = square(5);                              int y = square(5);

   // 编译后:
   // call square  ; 调用函数                        // mov y, (5 * 5)   ; 直接计算结果，不调用函数
   // mov result to y

   inline 的用法:
   (1) 头文件定义函数, 编译的时候就直接展开了, 不会出现我们在 2. 里面提到的有多个函数定义的问题
   (2) 性能优化, 因为直接展开了, 没有函数调用开销, 适合用来写小函数, 比 #define 这种 macro 安全, 而且性能几乎没有区别, 我习惯用 static inline 代替有逻辑的 macro

4. const

   const 表示是指编译器会阻止对该变量做语意上的修改, 如果你通过一些奇技淫巧用指针绕过的话, 还是可以改的

   const 修饰它左边最近的东西, 如果左边没, 就修饰它右边的, const int a; 和 int const a; 完全一样

   指针相关的 const, 这个很容易搞混

   指向 const 的指针
   #+begin_src c
    const int *p;   // 或 int const *p;

    int x = 5;
    int y = 6;
    p = &x;
    ,*p = 10;   // 编译错误，指向的数据不能改
    p = &y;    // 指针本身可以改
   #+end_src

   const 指针 ( 指针本身不可改 )
   #+begin_src c
    int * const p = &x;
    *p = 10; // 可以修改指向的值
    p = &y; // 指针本身不能修改
   #+end_src

   指向 const 数据的 const 指针 ( 双重 const )
   #+begin_src c
   const int * const p = &x;
   #+end_src

   在 cpp 里面, 这个也是类似的
   #+begin_src cpp
   PNG const & a = ...;
   #+end_src
   这里的 const 修饰的是 PNG, 然后从 a 开始往左读, 是 reference to const PNG, 不能改变这个 PNG 的值, 这个是用来传参的一个重要办法, 避免拷贝, 也避免改变传如的参数

   还有一个 const 的例子
   #+begin_src cpp
   bool operator==(PNG const& other) const;

   // 等价形式
   bool operator==(PNG const& other, PNG const* const this);
   // PNG const * const this, 左边的 const 修饰 PNG, 表示不改变 PNG, 右边的 const 修饰 (PNG const *), 表示不改变这个指针
   #+end_src

5. __attribute__

   这个不是 c 的关键字, 是给 GCC 的提示和指令, 是 GCC 的特性而不是 c 语言的特点

   __attribute__ 是 GCC 的编译器指令, 用于: 给编译器额外的优化提示/给编译器额外的优化提示/启用特定的语言扩展/提供调试信息

   因为我用的也不多, 我只在处理 DMA 无法 access DTCM 的时候手动放置 buffer 的时候用了一次, 所以这里多放了几个例子, 虽然我不觉得这些例子会用到, 但是别人用到的时候要看得懂

   基本语法
   ,#+begin_src c
    // 单个属性
    type name __attribute__((attribute_name));

    // 多个属性
    type name __attribute__((attr1, attr2, attr3));

    // 函数属性
    return_type func_name(args) __attribute__((attribute_name));
   #+end_src

   函数优化提示
   #+begin_src c
    // 1. 内联控制
    void __attribute__((always_inline)) fast_func() { ... }
    void __attribute__((noinline)) big_func() { ... }

    // 2. 热/冷函数提示
    void __attribute__((hot)) critical_path() { ... }   // 经常执行
    void __attribute__((cold)) error_handler() { ... }  // 很少执行

    // 3. 纯函数/常量函数
    int __attribute__((pure)) calculate(int a, int b) {
         // 纯函数：只依赖参数，无副作用
         return a + b;
    }
    double __attribute__((const)) pi() {
         // 常量函数：相同输入永远相同输出，且不读全局变量
         return 3.1415926;
    }

    // 4. 不返回函数
    void __attribute__((noreturn)) panic() {
         while(1);  // 永不返回
    }
   #+end_src

   内存布局控制
   #+begin_src c
    // 1. 指定段
    uint8_t buffer[1024] __attribute__((section(".dma_buffer")));
    const char str[] __attribute__((section(".rodata.custom")));

    // 2. 对齐控制
    uint32_t data __attribute__((aligned(32)));  // 32字节对齐
    struct S __attribute__((aligned(64))) { ... };  // 结构体对齐

    // 3. 打包结构体（取消填充）
    struct __attribute__((packed)) Packet {
         uint8_t cmd;
         uint32_t data;  // 通常会有3字节填充，packed取消填充
    };

    // 4. 弱符号（允许覆盖）
    int __attribute__((weak)) default_value = 0;
    void __attribute__((weak)) default_handler() { ... }
   #+end_src

*** 初始成员列表

在创立并初始化一个对象的时候, 一般流程是:
1. 分配内存 ( 为整个 object )
2. 初始化 base class 部分 ( 如果有 inheritance )
3. 按照声明顺序初始化所有数据成员 ( 始化的顺序是成员的声明顺序, 如果有初始成员列表, 使用初始成员列表的值进行初始化, 没有则默认  )
4. 执行构造函数体 ( 注意, 是构造函数题, 不是构造函数 )

初始成员列表性能上比赋值的办法快, 而且对于一些 const 的变量, 只能使用初始成员列表来做, 还有 reference 也只能用初始成员列表的办法初始化 ( 本质上也是个 const )

#+begin_src cpp
class MyClass {
private:
    std::string name;     // class object
    int id;               // 基本的类型
    const int version;    // const
    std::vector<int>& ref_vec;  // reference

public:
    // 在构造函数体内赋值
    MyClass(std::string n, int i, int v, std::vector<int>& vec) {
        name = n;          // name已经调用了 name 的默认构造函数, 即已经初始化了, 这里实际是 operator= 赋值
        id = i;            // 基本类型重新赋值, 影响比较小
        // version = v;    // const 的变量已经被初始化了, 这里是赋值, 但是 const 不能赋值
        // ref_vec = vec;  // reference 本质上是 const 指针, 理由同 const
    }

    // 使用初始成员列表
    MyClass(std::string n, int i, int v, std::vector<int>& vec)
        : name(n),         // 直接调用拷贝构造函数

*** reference

在底层就是 const pointer, 比如说 int & a = b;, 这个初始化操作在底层就是一个 int * const a = &b;, 然后之后在 cpp 里面我们每次用到 reference 的时候, 我们做的实际上都是对这个 const pointer 做引用, 然后指针的值 (b这个变量的地址) 是不能变的 ( const 修饰 ), 换句话说, 指向哪里不能再变了, 但是指向的地址存的值是可以改变的

这个就是为什么我们在初始化一个 class 的 reference 变量的时候要使用初始成员列表的方式初始化了

** more on constructor

可以在 default constructor 里面调用 custom constructor 去完成 initialization, 叫做委托构造函数

#+begin_src cpp
#include "sphere.h"
namespace cs225 {
    // delegating constructor: 委托构造函数
    Sphere::Sphere() : Sphere(1.0) {} // 在 initialization list 的位置调用 custom constructor

    Sphere::Sphere(double r) : r_(r) {
        // other logic
    } // custom constructor
}
#+end_src

讲一下这个语法
Sphere::Sphere() : Sphere(1.0) {} 里面最右边的那个冒号叫做: 构造函数初始化列表 ( constructor initializer list ), 是 cpp 里面唯一一个可以在对象 "出生瞬间" 初始化东西的地方, 相当于是说他定义了, 在这个对象一旦被声明和初始化的时候的 behavior 是什么

#+begin_src cpp
Constructor
  : initializer1,
    initializer2,
    ...
{
    // constructor body
}
#+end_src

这里面的每一个 initializer 可以是下面两者之一: 1. list initialization, 2. delegating initialization

再强调一遍 cpp object 的初始化过程:
1. 分配内存
2. 初始化成员 ( 只能在 initializer list 的地方干预, 否则就是执行每一个东西的默认的初始化 )
3. 执行构造函数体 {}

这个冒号后面的地方是我们唯一可以干预的地方

凡是 "对象一出生就必须确定的东西", 只能写在 : 后面, 比如 const, reference, delegating construction, base class object

体会一下 cpp 的哲学 RAII:
RAII = Resource Acquisition Is Initialization
资源的获取 = 对象的初始化, 资源的释放 = 对象的析构
